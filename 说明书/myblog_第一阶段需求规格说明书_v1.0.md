## 1. 项目目标、范围和不可改变的原则

### 1.1 【已确认】总体目标

从零建设长期可维护的独立 Wagtail CMS 内容站 `myblog`。**第一阶段以完整可用的 BlogPage 为业务落地点，以跨 Page 的公共 Block、公共媒体、人员、标签、搜索与归档为公共基础能力**；其他正式业务 Page（如 GuidePage）可在后续阶段增加，但其接入公共能力的接口需在第一阶段规划与检验。

- **Wagtail `Page` 是每篇内容的正式载体**。保留 Wagtail 原生 Page 树、Revision、权限、Workflow、预览、定时发布、发布、撤销发布、复制等生命周期。
- **PostgreSQL/Wagtail 是页面发布状态的唯一权威**。MongoDB 只保存声明外置的字段内容及其不可变版本，不独立决定哪些内容已发布。
- **复用的是基本 Block 的编辑、校验、渲染功能，不是跨 Page 共享正文内容对象**。每个 Page 的 `intro`、`body` 与业务组合独立，不能因为复用公共 RichText/Markdown 等 Block 而相互影响。
- **公共资源允许跨 Page 被引用**，如同一 Image、Document、Audio、Video、Person、Tag 可被多个 Page 使用；页面自身的引用关系、排序、图注、角色等属于相应 Page 的版本内容。
- 第一期不以旧项目迁移为目标：旧库、旧文件、旧配置和旧凭据均不得修改或复制；旧站仅用来理解功能。

### 1.2 【已确认】第一阶段必须交付的能力

1. BlogPage 核心内容、元数据、公共作者/标签/封面引用，完整 Wagtail 发布生命周期。
2. 全站公共基本 Block：RichText、Markdown、Code、Mermaid、Table、Image、Document、Audio、Video、Embed 等及其安全渲染、编辑协议（详见第 5 节）。
3. BlogPage `intro`、`body` **分别外置 MongoDB** 的不可变字段版本与 Wagtail Revision 精确绑定。
4. 全站公共图片、文档、音频、视频与 **RustFS 私有存储、统一受控交付**（真实集成须另行批准）。
5. 全站共享 Person、Tag 词库，按 Page 类型、目录筛选；不新建独立 Category 模型。
6. Page 独立图集 + `body` 内多个图集组合，公共媒体删除保护和引用追踪。
7. **受控回收站**：单 Page / 整棵子树可恢复；永久删除有专门权限。
8. 可用的基础搜索、标签筛选、BlogIndexPage 列表、年月归档前台，提供其他 Page 类型可注册的公共查询协议。
9. 中央单栏响应式 BlogPage 详情页，包括可选封面、简介折叠、正文混排、音视频、图集等。
10. 严格的数据一致性、权限、故障注入、回收站隔离和媒体引用保护验收。

### 1.3 【已确认】后续阶段，不得偷换为第一阶段必须项

- 评论、文章反应、阅读量统计、相关推荐、上一篇/下一篇、文章阅读进度、自动目录 TOC、可拖拽/折叠左右侧栏以及其他高级详情页互动。
- CodeBlock **真实可执行**的独立 Python/JavaScript 沙箱；第一阶段只提供代码展示及运行模式的编辑器/界面、状态与后端接口合同，不真正执行不受信代码。
- Elasticsearch 的真实集成（第二阶段）。第一阶段需有可用基础搜索及公共文本提取与发布投影，不得因推迟 ES 而省略功能。
- GuidePage 等其他业务 Page 的完整业务模型与模板；第一阶段应验证公共接口可被其他 Page 接入，但不擅自扩大正式业务范围。
- 旧站内容、数据库或媒体的生产迁移；会员、订阅、付费、订单、退款、在线插件市场等。

## 3. Page 树、业务字段、身份、人员与标签

### 3.1 【已确认】Page 树及类型边界

- BlogPage 可以创建在经允许的 BlogIndexPage、其他 BlogPage、GuidePage、XxPage 等父 Page 下；目录/业务 Page 也可按允许的类型规则自嵌套。
- `parent_page_types`、`subpage_types` 必须显式约束合法位置与递归关系；**不要强迫每篇 BlogPage 必须位于某个 BlogIndexPage 下**。
- `XxIndexPage` 管理 Page 树栏目层级，不再建立 `Category` 或 `BlogCategory` 等独立分类体系。
- 查询时区分**Page 实际类型**与**Page 树位置**，支持同时筛选。
- Wagtail Page/Revision/Workflow/权限为正式生命周期权威，不复制另外一套 Mongo 页面发布状态机。

### 3.2 【已确认】PAGE-DATE-01：所有自定义业务 Page 的必填成文日期

- 所有 `BlogPage`、`GuidePage`、其他 `XxPage`，以及各类 `XxIndexPage` 统一具备成文日期字段；**必填、不可为空、可由编辑人员修改**。
- 建议统一公共抽象字段名 `authored_on`（字段命名由 Codex 提案再确认），PostgreSQL `DateField`；不得用 `auto_now` / `auto_now_add` 在后续编辑中无意覆盖。
- 后台创建时“预填今天”只是**建议实现**而非已经确认的强制规则；保存时必须有有效日期。涉及历史数据或迁移时须制定补值计划，不能生成与必填要求冲突的迁移。
- `authored_on` ≠ `first_published_at`、`last_published_at` 或定时发布时间。前者表示成文日期，后者由 Wagtail 原生记录实际发布事件。
- 前台显示真实成文日期；栏目、归档默认按成文日期倒序，日期相同时采用稳定次级排序，**不采用“成文日期留空回退发布时间”的旧建议**。
- 成文日期随 Page Revision、草稿预览、审核、发布、恢复而一致切换；草稿修改不能提前改变前台正式页面。
- `HomePage` 是否属于需要 `authored_on` 的**业务内容 Page**，由 Codex 提案列为明确边界问题；不得暗自扩展到 Wagtail 的所有系统 Page。

### 3.3 【已确认】P0-A 自定义身份

- 用 Django 最小 `AbstractUser`，仅用于后台登录、权限、用户组；**不把 Person 或会员资料混入 User**。
- 单独公共 `people.Person` 表示公开人员资料；公开作者不必是网站后台登录者。
- 【建议/待审核】针对新 `myblog` 用 `identity` App、`IdentityConfig`、`identity.User`、`AUTH_USER_MODEL='identity.User'`；最终 app label、迁移依赖需在 P0-A 只读核查后确认。
- 首份 User 迁移须从项目现存迁移与新隔离数据库初始化路径推演，不允许假设本地已经或没有迁移过。

### 3.4 【已确认】F03-01 Person 与页面贡献关系

- Person 全站公共，包含姓名、可公开头像、简介、稳定标识等公共资料；准确字段由方案确定。
- 各业务 Page **各自独立**保存对一个或多个人员的关联，支持排序和公开贡献角色，如主要作者、共同作者、审校；具体角色词表可配置并由方案提出。
- 人员关联、顺序、角色必须进入 Page Revision、复制、恢复和审核测试。
- 公开贡献角色不等同 Wagtail Workflow 的真实审批权限或人员。
- 【F09 已确认】Page 恢复历史版本时，恢复当时的 Person 关联、排序和角色，**不回滚 Person 公共资料本身**；公开展示以 Person 当前有效资料为准。

### 3.5 【已确认】F03-02 / F03-03 全站统一 Tag

- 全站**一个 Tag 标签词库**；不建立另一个独立 `Category` 模型。
- 各 Page 独立维护自己的 Tag 关联；可按 BlogPage、GuidePage、XxPage、指定栏目及后代筛选标签及被引用的 Page。
- 同一标签在多种 Page 类型和多个栏目之间复用。前台搜索可组合 Tag + Page 类型 + 目录 + 成文日期。
- 编辑人员可以创建标签；管理员负责名称规范、去重与合并，合并后应维护正确关联与搜索投影。
- 后台标签使用情况展示关联页面、类型、位置和数量，但不得对无权限编辑人员泄露私有 Page 的敏感信息。
- 【F09 已确认】历史 Page 恢复关联到当时的 Tag 身份，而 Tag 名称等共享资料使用当前有效值，不强制为每篇旧文章做标签名称历史快照。

## 4. BlogPage 业务模型与外置字段

### 4.1 【已确认】F01 BlogPage 第一阶段核心字段

- Wagtail 原生标题、slug、SEO/搜索描述、发布/修订/权限状态。
- 必填 `authored_on` 成文日期；发布日期由 Wagtail 原生记录。
- `intro`：**Blog 专属 `BlogIntroBlocks`**，由公共 RichTextBlock、MarkdownBlock 组成，可重复、重排；不可与别的 Page 共享可变正文对象。
- `body`：**Blog 专属 `BlogBodyBlocks` / StreamField 组合**，直接列出公共基础 Block，**不要为了统一架构强加一层 `StructBlock`**；复合元素自身确有需要时可使用 StructBlock。
- `intro`、`body` 都外置 MongoDB；分别保留不可变字段版本，不因只改其中一个而无端重写另一个版本。
- 多人 Person/贡献角色/排序；全站 Tag；可选公共 Image 封面；页面独立图集以及正文内多个图集组合。
- `featured_image` 封面可选，默认放在标题上方；没有封面不渲染空白图框；使用 Rendition 和统一媒体权限。
- 内容、元数据、关联在草稿/预览/审核/发布/Revision/恢复/复制中的对应版本必须一致。

### 4.2 【已确认】D03 / D10 / D11：PostgreSQL 与 MongoDB 版本合同

1. PostgreSQL Wagtail Revision 对每个外置字段记录**精确字段版本指针**：例如 `intro_version_id`、`body_version_id`。正式发布状态与当前正式指针的裁决必须归属 Wagtail/PostgreSQL。
2. MongoDB 为不可变字段快照保存内容、schema/block 版本及必要校验信息；编辑新草稿产生新版本或复用未变化字段的既存版本。旧快照不可被改写。
3. 草稿预览、历史 Revision 和公开页面分别解析其绑定的字段版本；不能出现“已发布元数据 + 未发布正文”的混搭。
4. 发布前校验绑定的外置字段版本存在、可解析、引用及媒体权限有效。未通过时应阻止完成发布；发生跨存储中断时使用 Outbox、幂等重试、补偿和对账。
5. 不承诺 PostgreSQL+MongoDB+RustFS 存在跨存储原子事务；设计明确先后顺序、中断点、回滚/补偿规则和公众可见性安全边界。
6. Block 类型名、schema 版本、历史兼容转换保持稳定；重大数据变更应提供受控升级方案，历史 Revision 仍可读取。
7. 复制 Page 创建独立 Page 身份及自身的版本/引用关系；可以引用相同公共媒体/人员/标签，但不得把两个 Page 的正文变成一个可变共享对象。
8. 正式发布、撤销发布、定时发布、权限调整、恢复/回收站都要与搜索投影和媒体引用索引一致；索引坏了不能导致草稿泄露。

## 5. 全站公共基础 Block（第一阶段）

**【已确认】** 公共基本 Block 只负责内容数据结构、编辑交互、渲染及必要的资源能力；**整页布局和页面专属复合列表由各 XxPage 自己组织**。不同 Page 不能共享一份可变正文对象。

| 基本 Block | 第一阶段明确要求 |
|---|---|
| RichTextBlock | 通用富文本、链接、列表、常用排版及下划线等必要编辑功能；安全输出、全文提取 |
| MarkdownBlock | Markdown 编辑与渲染、代码围栏、数学公式、表格、Mermaid 围栏；安全 HTML 净化；原文可按结构保留 |
| CodeBlock | **一个 Block 两种模式**：默认只展示（语言高亮、行号、复制、长代码折叠）；可运行模式提供浏览器编辑、运行按钮、标准输入输出与错误状态、隔离执行服务接口；第一阶段**不真正运行未信任代码** |
| TableBlock | 文字、链接、公共图片、LaTeX 数学、受控 HTML、表头、合并/拆分单元格、行列增删复制与撤销重做、对齐、宽度、样式、移动端横向滚动；**不做电子表格公式，也不做首版 CSV 导入导出** |
| MermaidBlock | 通用 Mermaid 内容、渲染器/版本标识、图表预览、缩放/适配/全屏/折叠、主题、源码查看复制、SVG 导出、错误反馈；Markdown fenced `mermaid` 共用安全渲染器 |
| ImageBlock | 公共 Image 选择、图注与替代文本、Rendition、点击大图、响应式、受控访问、引用追踪 |
| DocumentBlock | 公共 Document 选择、标题/说明/下载、安全文件交付、引用追踪 |
| AudioBlock | 公共 Audio 选择、受控播放、基本播放器操作、媒体格式与访问校验 |
| VideoBlock | 公共 Video 选择、封面、播放/全屏、分段请求与授权 |
| EmbedBlock | 嵌入服务协议与安全嵌入策略；限制不可信 iframe/脚本、权限和 CSP 风险 |
| Gallery 复合能力 | 公共图片选择、排序、图注与 Lightbox 展示协议；正文组合由对应 Page 自己定义，不引入跨 Page 共享的可变图集正文 |

- Markdown 围栏中的代码默认作为**展示代码**，不自动当作运行型 CodeBlock。
- Mermaid 默认使用严格安全模式；渲染器兼容版本应可追踪，避免历史图表失效。
- TableBlock 的 HTML 允许列表须覆盖安全的表格合并语义（rowspan/colspan）且阻止 XSS；不能因安全净化破坏合并结构。
- 各 Page 对 Block 数量、嵌套层级和 JSON 大小可独立配置限制；具体阈值须由性能/压力测试确定，不在需求中擅自写死。
- 旧站存在 `raw_html` 独立块；**新站是否单独提供 RawHTMLBlock 并未最终确认**。Codex 只能提出受控方案，不能默认开启任意 HTML/JS。
- 公共 Block 的文本提取协议必须用于搜索，并能标注敏感/不可公开内容，按正式版本生成投影。

## 6. F02 / F06 / F11 / MEDIA-REF-01：全站媒体与安全

### 6.1 【已确认】第一阶段媒体能力

- 图片、文档、音频、视频均为**全站公共资源**，不建立 Blog 专属的图片/文件库。
- PostgreSQL 保存媒体元数据、访问策略和引用/权限相关信息；RustFS 保存原文件、Rendition、音视频对象；Page 仅保存公共资源引用与页面专属图注、顺序等。
- 第一阶段要求可上传、选择、查看/预览和交付四种媒体，并在 Wagtail 后台显示媒体使用情况；实际 RustFS 端到端验收须 E3 授权。
- Wagtail Image/Document 原生模型、Chooser 和 Rendition 优先复用；是否必须用自定义模型待 **P0-B** 最终评审，不能据此直接实施。

### 6.2 【已确认】F06 / F11 访问控制

- **RustFS 全桶私有**，不得向客户端暴露永久公开的原始对象 URL/密钥。
- 上传资源**默认受限**；资源权限独立于 Page 的公开/私有状态。
- 有权人员可显式批准一项媒体成为公开资源；私有 Page 引用公开资源**不会使资源变私有**，后台要避免误导。
- **公开 Page 引用仍受限的资源时必须阻止正式发布**，提示具体资源与引用位置；仍可授权编辑草稿/预览。
- 受限媒体经过资源/用户/访问上下文鉴权才能交付。短时签名 URL 只是临时凭证，不可视为永久权限校验。
- 原图、Rendition、文档下载、视频封面/字幕、音视频 Range 请求、API/Feed/缓存/CDN、后台预览、私人 Page 均不能绕过访问控制。
- 公开媒体许可、原图/派生图权限、签名 URL 有效期、缓存策略和 Range 访问要在 P0-B 技术合同中明确，不得采用“只限制文件列表页”的假鉴权。
- 如果共享资源从公开改受限，必须检查并提示当前公开 Page 的影响，设计一致性处理与必要的公开内容下线/失效策略。

### 6.3 【已确认】MEDIA-REF-01 引用追踪、删除保护

- **一张公共图片可以同时被 BlogPage 和 GuidePage 引用**；删除某 Page、移除图集项、删除某段当前正文，不能自动删除公共资源。
- 后台资源详情必须列出被哪些 Page 引用（在权限范围内）、引用位置、状态、涉及版本；至少区分：正式已发布、当前草稿、保留历史 Revision、回收站。
- 任一仍保留的草稿、正式版本、历史 Revision、回收站快照引用资源时，**禁止资源物理删除**。不完整或不可信的引用索引应**拒绝删除（fail closed）**。
- 引用抽取覆盖 Image/Document/Audio/Video、封面、页面独立图集、正文图集、RichText/Markdown、Table 等嵌套内容；Mongo 的不可变版本引用不能被 Wagtail 默认引用索引漏算。
- 页面永久删除只清理**该页面及其历史数据**对应的引用，不自动删除仍独立存在的公共媒体；其他 Page 的引用必须保留。
- 媒体本体与 Rendition 等派生对象须有一致的保留/销毁规则；定期对账、修复和补偿，并保留审计记录。
- 对外部 URL 图片/文档与内部托管资源的识别、引用索引能力差别，Codex 应明示设计，不得错误承诺能够保护外站资源。

### 6.4 【已确认】F03-04 两种图集

- **页面独立图集**：由所属 Page 独立维护图片列表、排序、图注、选图和显示选项；Page Revision 需包含相关关系。BlogPage 的独立图集默认在 `body` 正文后展示。
- **正文内图集**：可在同一 `body` 的任意位置插入多个图集组合，属于该 Page 的外置 `body` 字段版本；不与其他 Page 共享可变内容。
- 两种图集都使用公共 Image、Lightbox/响应式基础能力和 MEDIA-REF-01；复制 Page 复制排列关系而不是复制 RustFS 原始图片。

## 7. F08 / F09 / F10：Revision、回收站、复制与恢复

### 7.1 【已确认】F08：一个 Page 版本对应完整业务内容

正式页面在任何时刻应看到**同一发布版本**的：成文日期、作者及其排序与贡献角色、标签关系、封面、图集、`intro`、`body`、SEO 等。保存草稿不能提前改掉当前公开内容；审批拒绝、定时发布、历史恢复和复制也必须遵循同一规则。

### 7.2 【已确认】F09：历史关联与全站公共对象区别

恢复历史 Page 时，恢复当时选择的 Person / Tag **身份和关系**，以及当时 Page 专属的角色、排序、图注；不强制将 Person 姓名、头像、简介或 Tag 名称等**共享对象本体**恢复到过去值（显示当前有效公共资料）。媒体则按资源身份保留并受历史引用保护。

### 7.3 【已确认】F10：受控回收站

- 第一阶段实现：单 Page 与整棵子树回收、查看、恢复；**恢复后默认未发布**，须通过 Wagtail 原生权限/工作流重新发布。
- 删除前显示受影响页面数量、页面类型、后代、发布和权限情况；越权、树约束和并发冲突须拒绝或要求管理员解决。
- 回收中的 Page、子树在前台 HTML、API、搜索、标签、归档、Feed、缓存、定时发布等入口均不能被公众访问；已安排的定时发布和工作流不能自行“复活”内容。
- 回收站**没有自动清空期限**。永久删除仅限拥有专门授权的管理员，二次确认、审计和引用保护必须成立。
- 恢复时保留原页面身份、子树结构、顺序、历史 Revision 与 Mongo 外置字段版本；父节点不存在、slug 冲突、类型不允许时必须暂停并让管理员选择合法处置，不覆盖现有页面。
- **回收站中和保留历史 Revision 的所有媒体引用继续保护**；进入回收站不是物理删除媒体的理由。
- Wagtail 原生的 Page 删除（包括 Wagtail 8.1 API v3 DELETE）为硬删除：新站**不得直接暴露可绕过回收站的普通删除路径**，包括后台、API、批量操作、管理命令及应用代码。
- 【技术方案待审核】回收站如何保留原 ID / Revision / 子树并保证 Wagtail 模型可用，必须由 Codex 对比状态隔离、隐藏树/逻辑删除、独立保留机制的可行性及风险，**不能未经评审直接重写 `Page.delete()` 或假设 Wagtail 自带回收站**。

## 10. 安全、可靠性和非功能要求

### 10.1 【已确认】安全边界

- 统一权限决策不得跳过 Wagtail Page/Collection/Site 访问限制。媒体访问另按独立资源策略鉴权；后台“引用了哪些私有 Page”也不能对无权用户暴露敏感标题。
- 搜索、API、缓存、预览、文件交付、Range 请求、Rendition、媒体签名 URL 和回收站均进行直接绕过测试。
- Markdown/Table/Embed/HTML/Mermaid/Code 严格防 XSS、危险 iframe、脚本执行、SSRF 和不安全下载行为；真实代码运行服务第二阶段隔离开发。
- 外部链接、外部图片不应被误认作托管资源；明确风险及可用的策略。
- 不记录或返回真实密钥、Token、生产连接串、用户私密数据。日志对媒体 URL 凭证做必要脱敏。

### 10.2 【已确认】一致性与故障模式

- PostgreSQL 是正式发布与 Revision 权威；Mongo 内容版本不可变；RustFS 对象独立保留；Redis、搜索/缓存只是可重建辅助。
- 对草稿保存、预览、提交审核、审批拒绝、定时发布、正式发布、撤销发布、复制、删除/回收、恢复执行故障注入，验证不会出现公开草稿或部分发布。
- Outbox/异步事件必须可重试、幂等、有补偿/对账；重复事件、延迟事件与并发更改不得覆写较新的正式状态。
- 媒体引用保护和权限失效时应“拒绝不安全操作”，不能默认允许删除或公开交付。
- 保存编辑草稿可以有诊断性失败，但不能伪称发布成功；避免让缓存/搜索决定网站正式显示版本。

### 10.3 【待设计】性能与容量

- Page 各自配置 Block 数量、JSON 大小、嵌套深度上限；数值经基准测试决定。
- 需评估大型 Table/Mermaid/Markdown、音视频文件、图片 Rendition 并发、全文提取、历史引用索引规模、回收站子树操作与查询性能。
- 明确分页、索引、幂等记录保留、媒体下载带宽/Range、缓存时效和失效流程；**不在本文件擅自确定数值 SLA**。
