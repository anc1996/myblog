# myblog 全站数据分析指标与排行精选需求规格说明书

**日期：2026-11-23（2026-11-24 状态同步）｜状态：已确认并完成第 1–3 期实施（代码、迁移与隔离测试已落地；后续冻结新增表结构，仅做共享层去硬编码与真实线上观察）。** 本文定义要做什么、数据怎么算、谁能看以及怎样验收。技术细节见[可行性方案 RFC](myblog_全站数据分析与文章评价排行可行性方案_RFC_2026-11-23.md)。本需求不变更既有内容发布、权限和回收规则。

## 1. 目标、范围与现有底座

系统要回答四个问题：读者从哪里来？他们读了什么、做了什么？哪些内容值得推荐或复核？编辑和审核工作哪里积压？流量、阅读质量、技术时效和治理结果分别展示，不用一个数字替代编辑判断。

### 1.1 以页面能力接入，不把分析做成博客专用功能

| 分析对象 | 典型页面 | 指标与用途 |
| --- | --- | --- |
| 内容详情 | `BlogPage`、`GuidePage`、`ProjectPage`，以及未来继承 `CustomBasePage`、注册 `TypeAdapter` 并声明分析能力的详情页 | 基础流量、阅读深度、四档文章评价、类型专属转化；可配置入榜和精选资格 |
| 聚合入口 | `HomePage`、`BlogIndexPage`、`GuideIndexPage`、`PortfolioIndexPage`、`TagIndexPage`，另含站内搜索和作者专栏入口 | 入口 PV、日 UV、来源、内容卡片曝光、进入详情次数、入口导流率；不计算文章完读率，不和详情页竞争榜位 |

对首页、栏目、标签路由等使用稳定入口标识。`HomePage` 当前直接继承 Wagtail `Page`，不是 `CustomBasePage`，应显式注册为入口，不为了统计改继承；标签目录与具体标签结果可以分开统计，任意查询参数和翻页路径不生成无界入口。入口导流率 = 有至少一次归因成功的详情到达的入口访问数 ÷ 有卡片曝光的入口访问数；卡片点击率 = 有点击的卡片曝光数 ÷ 可测卡片曝光数。同一浏览可能先计入口 PV 再计详情 PV，但不能把前者转记为后者的阅读或把两边 UV 相加。

- **Hacker News**：FAQ（`https://news.ycombinator.com/newsfaq.html`）公开基于时间衰减的原则。本文的完读、跳出、榜单参数和精选权重都是 myblog 自定义，不需要接入外部账号或获取外站用户数据。

## 2. 详情页指标与统计口径

### 2.1 传播、时间窗和访客

- **PV（浏览次数）**：已通过公开资格检查的页面在浏览器实际进入可见状态，且通过过滤后的一次浏览。建议同站点、页面、访客 30 秒内刷新合并；浏览达到 30 秒本身不新增 PV。重试、同次浏览的滚动、资源加载、预取和健康检查不算新 PV。缺少浏览器事件的访问不补猜，后台注明覆盖限制。
- **UV（独立访客数）**：同一统计日、同一范围内，对短期访客键去重。当天看三篇文章，单篇 UV 各可加 1，但站点 UV 只加 1；跨页面类型也不叠加出全站 UV，单独在站点与类型范围去重。访客代表可识别的浏览器/身份，不承诺等同自然人；清理浏览器标识、跨设备、登录状态变化可能影响估算。
- **时间窗**：按站点统一报表时区，首发建议沿用项目 `Asia/Shanghai`，自然日零点切换；“近 7/30 日”看板默认含今天，明确今天未结算。昨日、近完整周期、今日同时段对比需明确标记。累计从本功能采集启用日开始；报表标出数据截至时间、缺测区间、口径版本，只有已覆盖且确无事件才显示 0。
- **单页卡片**：PV 提供今日、昨日、近 7/30 日、累计；UV 提供今日、昨日和每日趋势，当日未结算可标“待结算”。跨日只展示**访客日**，即同一范围的每日 UV 相加，不计算跨日独立人数。同一人周一和周二各来一次，是 2 访客日，不是 2 个独立访客。
- **范围与归属**：按访问站点及当时的内容类型、栏目标识归类。详情用 `document_uuid` 稳定识别，保留 `page_id` 定位；改名、移动、正常更新不重置页面累计，历史流量不挪给新栏目；复制为新身份从零开始。正文版本使用 Wagtail 正式 `live_revision`，同一页面有待审草稿时，只有仍公开的旧正式版可被计入；不拿草稿数据补齐指标。

### 2.2 深度阅读、来源与互动

一次“阅读访问”指一个被接纳的详情 PV 对应的短期阅读会话；同次访问只记一次有效、完读、跳出标记。以浏览开始日归属，跨午夜续读不另开 PV 或 UV，次日真正新访问才计次日。每次有心跳或可验证终态才进入可测样本，未成功回传的不当作跳出；样本封账前看板标“暂估”。多篇/多日的整体页面指标用分子与分母分别求和后计算，不平均每日百分比。

阅读范围只取共享详情模板的 `detail_body`：正文中的指南步骤和内容积木计入，正文外的引言、摘要、独立图集、相关推荐、标签和评论不计。首屏可见全部有效正文的是短正文，按停留判定；空正文、渲染失败或标记不合格只计合格 PV，不计完读或发放评价凭证。

| 指标 | 定义与展示 |
| --- | --- |
| 有效阅读与有效阅读率 | 可测访问中，活跃前台停留超过 **15 秒**，或真实滚动超过正文 **50%**；同一次只计 1。比率 = 有效访问数 ÷ 可测访问数。短文首屏无需滚动时按停留判定，不能页面一打开就算有效。 |
| 完读率 | 达到正文末端标记（评论区之前，没有评论也保留标记），且活跃停留至少 **10 秒**，计为完读；完读率 = 完读访问数 ÷ 可测且有正文末端标记的访问数。评论区、页脚、相关推荐不算正文字数或滚动距离。短内容达到停留要求即可判定，打开时命中锚点不立即算完读。 |
| 平均阅读时长 | 总活跃阅读秒数 ÷ 有可信时长样本的访问数。仅计页面可见、有活跃信号的时间；切后台、锁屏、长期无心跳不累计；每次会话最长计 30 分钟。作榜单特征时再按类型与内容长度归一化、对极端值封顶。 |
| 详情跳出率 | 报表中标注“短读离开”：已完成观察的访问中，停留不足 10 秒、正文进度不足 25%、无有效/完读标记且没有合格互动、站内后续到达或指定外链动作。除以有足够信号判定这些条件的已结束访问数。未知不计入跳出；它不是全站单页会话跳出率。 |
| 阅读漏斗 | `可测阅读 → 正文 25% → 正文 50% → 正文 90% → 正文末端`；每档统计达到该阶段的同一队列人数（实际为访问数，默认标“次”）。末端触达和满足停留规则的完读分别展示；短内容以“不适用滚动档”另列，不与长文混算。展示采集覆盖率 `可测访问 / 合格详情 PV` 和样本量。 |
| 来源构成 | 按 PV 对每次访问归一个主来源。站内首页/列表、搜索、作者专栏、标签、精选/榜单、其他；站外搜索引擎、社媒、其他站点；无可信来源归“直接/未知”。仅使用有限站内入口枚举、外部注册域名或域名大类；丢弃路径、查询串、片段、凭据和低频/可识别的子域，不从来源 URL 存搜索词。渠道 UV 不默认展示，若加则按渠道去重且不可加总。 |
| 评论和作者回复 | 有效审核评论为当前批准版本公开可见且回复链可公开的评论（包含仍展示上个批准版本的待审编辑），不计隐藏、软删、未公开或驳回的内容。治理视图另外按主评论记录统计总量、状态、待审版本，评论与版本分别归类。窗口新增公开评论按首次审核公开时间计，撤销/隐藏后从有效统计和评分中剔除，不覆盖治理审计。作者回复率 = 同一窗口首次公开的读者根评论中，已获发布贡献者的有效公开回复的根评论数 ÷ 该批有完整 7 日观察期的读者根评论数；站方回复另列，不把 `is_official` 自动当作者。不可可靠识别贡献者时标“未识别”。 |
| 四档文章评价 | **优秀 / 良好 / 及格 / 差**。好评指优秀与良好，“及格”不是差评。展示分档、当前有效票数和样本范围；后台口碑分带样本量和规则版本。评论赞踩、文章评价和内容举报互不替代；独立赞同、收藏不是四档评价首发的前置条件。未启用标“尚未采集”。 |

### 2.3 按类型增加专属指标

| 类型 | 指标及计算办法 |
| --- | --- |
| `BlogPage` | **长文完读率**：发布正文可见文本不少于建议的 1,500 字符（不含代码、HTML、评论；解析规则记版本）时，才进入长文分组，按 §2.2 计算。**代码复制次数**：只记复制控件成功回调，按访问与代码块防重复；不采集复制内容。**Mermaid 查看次数**：成功渲染且进入视口，或用户主动打开后实际展示；单次阅读每图一次，不把初始化算查看。 |
| `GuidePage` | **步骤完成度**：用发布 Revision 的步骤清单及稳定块标识；显式“完成此步”的访问数与步骤完成比例分开显示，完成度 = 完成的必做步骤数 ÷ 该版必做步骤数。仅展开/滚动称“步骤触达”，不声称实操成功；同一会话同一步最多一次，不将新旧步骤串合。**课件下载**：`CustomDocumentBlock` 分“点击尝试”和“授权后成功交付响应”；由页面、版本、附件归属和下载动作去重，合并分段请求、重试，不把鉴权失败、公共附件在另一页下载或拿到链接当本指南下载，不能主张文件完整落盘。**时效健康度**：按公开 `last_reviewed_at`，335–364 日提醒、达到 365 日逾期、缺值单列；保存草稿、重新发布或默认日期不等于编辑真的完成技术复核，默认/历史无法证明时需人工核对。 |
| `ProjectPage` | **仓库与 Demo 转化**：分 `repo_url`（包含 GitHub 及其他仓库）、`demo_url`，成功展示该链接的可测访问是各自分母，有有效点击的访问为分子，同一访问每种一次。只说明“从本站点击”，不推断对方加载、注册、Star 或部署成功。**技术栈热度**：按已发布的 `primary_language`、技术标签分组，展示 7/30 日有效访问、互动、链接点击率及样本；多标签可重叠，不用于拼全站总量；模型 `star_count` 徽标不纳入站内流量。 |

### 2.4 四档评价的互动和版本边界

- 在 `detail_shell.html` 的新增正文结束标记之后、评论区之上显示四个带文字的表情按钮，由 `TypeAdapter` 的分析能力声明控制。博客、指南、项目走同一组件，与评论开关无关；聚合入口、预览和非公开页不显示。
- 首发推荐有效登录会员投票，游客只看按钮及登录提示；后续若开放受控访客，需独立授权、短期 HMAC 浏览器令牌（用密钥签名的随机浏览器凭证）、阅读门槛、原子限流和反作弊验收，不把浏览器等同自然人，不与会员重复累计。
- 同一页面、同一账号只有一个当前档位。点击不同档切换，点击当前档取消。新增总票 `+1`，切换旧档 `−1`、新档 `+1` 且总票不变，取消总票 `−1`；重复请求不改变结果，反复切换不增加榜单动作分。新投票和切换须有当前正式版的可信阅读凭证，作者及可核验的发布版贡献者不得自评。
- 新正式 Revision（页面的历史版本）不继承旧版口碑。读者重读新版后可重新评价，旧版现存票汇总会随改投、撤销或销户变化，不能当作该版发布时的历史口碑。历史只读已存档的无身份榜单或审批证据。草稿、预览和未到时间的排期不改变仍公开旧版的评价。支持校验本人状态，不公开单个评价者。

## 3. 排行与精选：系统找候选，编辑定推荐

### 3.1 榜单

所有榜单基于合格流量和已确认互动预算分，后台可看原因、分母、版本、快照时间；不通过公开资格与风险筛查的记录不进入公开榜。新内容不因缺失数据被判低质；负向信号低样本不推断质量。

| 榜单 | 建议规则 |
| --- | --- |
| 实时/今日飙升 | 每 5 分钟尝试刷新。最近 6 小时的合格动作按小时计分，例如有效阅读 1、有效读者评论 3；动作限额，不将任何评价写操作当作加分动作。同口径窗口增幅单独展示，基线低于 5 不显示百分比。排序示例 `Σ[小时动作分 / (2 + 距该小时结束的小时数)^1.3]`（当前未结束桶按年龄 0）；今日榜限当地今日内的桶。衰减针对流量新鲜度而非 `authored_on`，并应用 §3.4 的口碑降权。 |
| 近 7/30 日综合人气 | 默认采用最近 7/30 个已完成统计日，按类型出榜。用有效阅读、可信互动和可比较的类型转化，不按 PV 单排；无可比较转化时调整公共指标权重。应用 §3.4 的口碑降权。全站总榜先按类型归一；类别样本不足时分栏，不把下载数或仓库点击直接与博文互动比较。指南人气上榜不等于获编辑精选。 |
| 深度干货口碑榜 | 跨类型混排默认关闭。展示完读、相对时长、短读离开和当前正式版的可信评价。小样本显示“观察中”，不把无评论、无评价或缺测当作高口碑或差评。 |

榜单建议最小样本：飙升窗口至少 5 份有效阅读访问；7/30 日人气榜至少 20 访客日且无待处理重大流量异常；低样本提示“观察中”。并列按分值、有效样本量、首次正式发布时间、稳定页面标识依序打破。推荐位/榜单带来的曝光需要单列来源；首发建议剔除可识别的首页精选与榜单导流对候选评分的贡献，避免上榜后只因额外曝光一直在榜，流量总报表仍正常计入。

### 3.2 精选分与准入门槛

建议每日在日表结算后计算一次，固定最近 **30 个完整统计日**、按类型与内容长度/难度分组。精选准入和评分使用当前正式 Revision 的阅读样本；当前版本样本不足可人工提名，页面历史总量仍可作背景，不能替新版证明质量。精选分是编辑优先复核的排序，不是内容价值的定论。

`Quality Score = 100 × (0.35C + 0.20T + 0.15L + 0.20I + 0.10F)`

- `C`：平滑后的完读率，`(完读数 + 20 × 同组完读基准)/(完读可测样本 + 20)`；`T`：平均活跃时长除以同组参考时长后截到 0–1；`L`：`1 − 平滑短读离开率`（同样加 20 份同组基准样本）；`I`：以当前版可验证、仍公开的限额读者评论率为基准，结合有足够证据的四档评价口碑，评价权重和样本保护见 RFC；不累计评价点击，也不把没有可信版本归属的互动归给新版；`F`：指南复核未到预警为 1、临期为 0.5、缺失或逾期不自动入围，博客/项目首期统一为 0.5。
- 基准、权重、过滤规则、样本量和分值版本一同保存；同组数据不足就使用审批后固定的类型基准或标“暂不评分”。数据源未上线、缺测严重、无可比基准时不冒充满分或零分；同一版已支持的互动指标采集完整但实际无互动才记 0。
- 首发自动候选必须达到：**最近 30 个完整统计日内 ≥100 访客日、≥60 可测详情访问、覆盖率 ≥60%、≥60 个可测完读样本、完读率 ≥50%、精选分 ≥70**；页面须正式公开、非别名、非回收。样本、分母和门槛使用剔除可确认精选/榜单导流及异常后的同一范围；不以历史总量或跨日 UV 补门槛。
- 指南须处于有效复核期（不足 365 日且有可核验复核）；已确认且未解决的严重内容问题、待核实的高风险流量异常、§3.4 的高流量低口碑告警阻断自动候选。评价、举报尚未启用时各自标“无该信号”；垃圾评论被驳回或评论被踩不等于文章质量问题。疑似刷量按风控单独隔离、告警并留痕。

### 3.3 精选工作台与前台联动

1. **候选池**：每日批量出清单，按站点、类型筛选，可查标题、有效版本、样本、门槛差距、风控状态、入围原因和数据时间。例如“完读率 78%（78/100）· 7 日有效互动 17 次 vs 上一周期 5 次（+240%）”；无足够基线不显示增幅。每日重跑不重复建候选；同一页面与公开版本保留一次有效待审核项，更新证据不覆盖编辑决定。
2. **编辑复核**：主编/超管检查技术正确性、时效、标题与内容是否相符、附件/外链可用性和版权/治理问题；可「设为精选」「置顶首页轮播」「暂不入选」或取消推荐。冷门优质内容允许编辑手动提名，补理由越过流量门槛，不能越过公开、版本和已确认重大风险限制。暂不入选要保留原因，建议同版本冷却 14 日；并发审批只允许一个状态结果，重复点击不重复推荐。记录操作人、时间、审批的正式 Revision、证据快照、站点、投放位置、优先级、有效期和变更原因。
3. **发布展示**：首页轮播、精选指南、精选项目和栏目精选都只读对应位置的已批准池，先有效置顶，再按优先级与质量分补位；轮播至多 8 项。不足就留空，不从最新列表补精选。“最新文章”保留独立区域；栏目导航和热门标签也不属于精选。所有区域均校验当前站点和祖先公开资格，栏目精选再查当前栏目范围。各位置可分别撤回。
4. **失效处理**：下架、回收、设为私有、跨站移动或正式 Revision 更新时，旧推荐不能依赖缓存继续露出；更新版本先标待复核，预览/草稿保存不触发旧正式版撤销。指南逾期暂停精选，恢复或重新发布不自动恢复旧推荐。任何方式最多自动填充经编辑批准的记录，不绕开 Wagtail 内容审批，也不由分析修改 `live` 或工作流。

### 3.4 高浏览低口碑的降噪规则

四档分数不能直接取生平均：先加少量虚拟样本做贝叶斯平滑，也就是用固定参考口碑缓冲小样本；再用 Wilson 下界保守估计差评占比。只有 1–2 个差评时不触发负向规则；已有足够多差评并接近阈值时，一票可以跨线，但不能单日触发降权或阻断。RFC 规定连续健康日评及不同的解除阈值；缺测不能解除活动告警。具体参数待定稿。

高 PV 仅用于识别需要解释的流量，不作为质量分。样本充足且低口碑时，热榜与飙升榜按可解释因子降权；高 PV 且低口碑时告警、阻断自动入围，并暂停该版本既有精选投放，交主编/超管复核。低完读或高短读离开是加重证据，不把不可测访问当短读。

为避免建站初期会员评价样本不足导致降噪长期空转：最小投票数、高 PV 阈值和观察预警阈值均由站点配置管理（默认保持保守值，允许初期调低**仅进后台人工预警**的观察阈值，但不降低自动降权的统计保护）；同时支持独立的「高浏览低完读 / 高短读离开」辅助预警，即使评价票数未满也能先提醒主编核查标题党或水文。编辑可按同一站点和正式版本留理由、限时豁免投放，或确认下榜；豁免不能绕过公开资格、未解决的严重违规或重大刷量风险，也不会让系统自动批准。该规则不修改页面发布状态、不处罚作者，不在前台给文章贴“标题党”标签。

## 4. 作者、编辑和审核人员

**人员归属是三件事：** `people.Person` 是内容署名与贡献身份，Wagtail `Page.owner` 加 `Ownership` 决定作者数据访问范围，后台操作人是用户账号。仅用经过确认的绑定关联 `Person` 和账号，不按同名或公开署名授予权限；署名是合著不等于可看他人分析，所有权转移后旧所有者立即失权。

| 维度 | 口径与使用方式 |
| --- | --- |
| 作者产能 | 按正式首发/月度实际再发布分别统计；按主笔、合著、审校、翻译、编辑或项目分工分列。同一人同页面同角色一次，全站作品次数按页面去重；多人署名不相加为全站发文量。以发布快照保留当时贡献角色，改署名不追改历史；可按当前归属另看。更新率按实际正式发布，不按 `authored_on`、草稿保存或更名推算。 |
| 内容贡献与维护 | 字符数、步骤数、关联附件数记录为**作品规模**；只有明确记录到个人的动作/分工才能称个人贡献，不把全篇字数都算给每名合著者。按月显示最近首发、更新和已确认复核，默认距上次更新 90 日只作运营提示，非考勤。指南 365 日逾期清单按已发布审校关系/维护责任人分派，未分派单独列。 |
| 作者质量 | 同类型同窗看篇均 PV、篇均日 UV 或篇均访客日（注明统计范围）、按阅读访问加权的完读率、入选精选率及四档评价分布（好评 = 优秀与良好，分母为有效四档评价）。这些是作品样本，不是作者等级；低样本不作质量结论，也不直接用于绩效、封禁或权限调整。 |
| 审核效率 | 文章使用 Wagtail 工作流任务与送审 Revision；评论以 `pending_submitted_at`、`CommentReviewAction` 与目标版本计算。积压是在观察点尚未决的待审任务/版本数，按等待时长分桶；处理耗时为提交到首次终态处理，统计均值、中位数、P90 和超时数；再次送审按新一轮计，取消、自动处理、无可靠时间记录单列。同窗驳回率 = 已驳回 ÷（已通过 + 已驳回），不要用积压数作分母。 |
| 治理记录 | 栏目范围内查看受限作者的可核验审批、确认违规与回收/恢复/销毁操作，以及异常流量告警、处理状态和整改历史；不将正常退修、举报数量或系统猜测视为违规。可按授权范围由 `Person` 看内容贡献、由工作人员账号看处理工作；风控只展示日级波动、原因和处理人，不显示访客 IP 或请求轨迹。 |

## 5. 后台工作台与前台展示

| 界面 | 应提供的功能 |
| --- | --- |
| 全站大盘 | 主编/超管按站点、类型、日期、入口/详情和来源筛选，默认近 7 日；PV/日 UV、评论/互动趋势，按类型 PV 柱状或占比图，来源分布、热榜、精选队列、逾期指南及异常流量。比较等长窗口，今日比较昨日同一时点，告知统计延迟和采集覆盖率；点击趋势或类型可到授权的页面列表。 |

**权限。** 主编须显式授权，不能从 `is_staff` 推断；普通编辑/审核员只看授权站点、栏目或任务。`Authors` 的列表、单页接口、聚合、缓存与导出都由服务端复用 `Ownership`；回收数据还要求既有回收查看权限。主编/超管才可审批精选、处理口碑告警及豁免。

**独立开关。** 阅读数字默认关闭，内部指标跑稳后才按配置开放延迟汇总的紧凑累计（如 `1.2万阅读`），小样本隐藏，不公开精确 UV、来源或治理信息。评价按钮另设站点、类型和页面开关；验收后可先开启评价、仍关闭阅读数字。按钮显示不等于公开分档票数，首发建议只回显本人选择，不公开票数与口碑分。评价关闭后不接受新增/切换，应保留登录用户撤销本人评价的途径。采集停用、评价投票和评价进入榜单均可独立控制；评价开关不跟随 `allow_comments`。

## 6. 采集、性能、隐私与删除

### 6.1 公开准入和高性能数据流

1. **页面不等统计。** 公共模板提供轻量采集能力，受控制的浏览器异步请求在页面可见后提交浏览与阅读信号；正文渲染和 HTML 响应不等待 Redis、分析数据库或远程服务。仅成功的规范公开页面可以发出有效采集上下文，缓存页面不能把会话标识分享给其他读者；预取、HEAD、重定向、非成功页、预览、编辑页面、历史 Revision、未上线排期、回收提示、页面或祖先受限、Wagtail 别名、无法验证发布版本的请求均排除。工作人员正常以公众身份浏览与后台预览不是一回事；可加明确的内部访问排除配置。
2. **服务器校验。** `TypeAdapter` 提供类型与公开元数据，增加显式分析能力声明（入口/详情、指标集、版本、可选转化），未注册或未声明则不采集；业务 App 声明，不在公共模块写博客分支。采集绑定站点、页面身份、正式版本和有限有效期；客户端声明的 URL、类型、时间和指标不得直接信任。进入异步采集时复核准入，worker 批量核验 PostgreSQL/Wagtail 的页面、祖先、站点和版本/状态代次。可复用 `content_lifecycle.public_access` 的规则与 `IndexListingService` 的公开范围，不能仅信搜索投影或旧缓存；验证失败则不计。迟到事件若无法证明当时及接收时仍具资格，保守丢弃、记录匿名原因计数；已落库的历史合法流量按保留策略处理。
3. **Redis 接收。** 独立命名空间，短超时和容量限制；原子处理事件去重、30 秒窗口和限流，累积当日/当小时增量。基础事件、短期会话序号、动作类别均限制大小和时间；阅读上报用最新绝对值（最大滚动、活跃累计），重复和乱序只取合法更新，不能重复加时长。待复核计数按页面与公开状态代次隔离，不能在确认前并入全站 UV 等无法反扣的合并值；统计期内保留必要的短期去重贡献，复核拒绝或已确认刷量时剔除后再生成范围计数，超期不能还原则标记口径受损而非猜测扣减。就绪批次原子冻结并形成有稳定批次 ID 的待处理队列；事件贡献在摘取前不能无记录丢失，也不能跨两个批次重复领取。短期访客键只留在限时去重区，不进入持久批次队列。JS 禁用、拒绝采集、主动拦截和丢包不估算为零，报表标覆盖限制。
4. **PostgreSQL 批量结算。** `PageAnalyticsDaily` 拟按 `site_id + page_id + stat_date` 唯一保存分子、分母、阅读秒数、日 UV、类型和版本口径；必要时加受控的版本、入口、来源与小时子汇总，禁止用高基数字段任意分桶。`PageAnalyticsTotal` 拟按 `site_id + page_id` 唯一保存可累加总值和计算水位（已处理到的时间/批次）；页面展示从总表或批量读取缓存，不扫描明细、不逐卡片查询。版本与页面聚合分别计算，含多版本的一天不能通过加各版 UV 得出页面 UV。站点/类型/页面日 UV 按各自范围在短期 Redis 集合或经确认的等价去重结构累计，并批量保存绝对计数（同范围按水位更新）；不按小时、批次或页面把 UV 直接相加。评论、正文互动、审核等业务事实由各自 PostgreSQL 记录裁决，采集组件只读或接收提交后事件，不能成为第二套状态源。
5. **幂等与并发。** 幂等表示同一批次重试不会重复计数。数据库用唯一批次收据在同一事务完成日表、总表及必要校正，提交后才确认队列；提交前失败可重试，提交后确认丢失靠收据跳过。保留批次收据至少覆盖所有可重放期，待处理批次不能先被 TTL/剪裁清走；不可把 Redis 清零后才写 SQL。批处理按固定键顺序更新、小事务分片；普通计数不抢 `ContentMutationGuard` 全局锁，生命周期敏感写入要与现有锁顺序兼容。回收/销毁与汇总需有共同的数据库对象存在/状态代次检查与相同顺序的行锁或等价条件更新，防止销毁后被迟到批次重建。精选动作并发核验正式 Revision，与页面发布、撤回、回收逻辑分开职责；缓存只在提交后重建/失效。

**故障要求。** PostgreSQL 是正式报表聚合与精选决定的持久来源，Redis 实时计数可降级，不能当成发布或推荐权限依据。MongoDB 保存不可变内容字段版本、RustFS 存文件，不存访问事件或新增旁路权限；SQL 回滚不撤回跨存储对象，本功能不在回滚回调里删正文/附件。健康时建议 95% 可滚动结算的指标从可提交到可见不超过 5 分钟；阅读观察期和日 UV 封账支持定时执行与开机补跑（适应非 24 小时开机的本地/WSL2 环境），不承诺无损或秒级排名。Redis 故障、淘汰或超出队列上限时，正文正常提供，报表显示最近持久快照和缺测/延迟；缺测日单独标记且不计入均值分母，不因偶发单日停机永久锁死 30 日候选（具体健康天数下限由 RFC 规定）。不能回退到逐请求同步写 SQL，也不能用零覆盖快照。监控队列长度、最旧未处理时间、丢弃原因、批次重试、入库和查询耗时；恢复时按批次补入，仅无法恢复的区间标缺测。验收以隔离环境压测为准，初始建议测试 100 公共详情请求/秒、15 分钟集中访问热门页，页面无额外同步分析写入或按卡片额外查询，页面 P95 延迟较采集关闭基线增幅 ≤5%，后台常用 30 日聚合查询 P95 ≤2 秒（相同数据和负载）。

### 6.2 防刷及最少数据

- **人流判别是近似。** 过滤已知爬虫、预取/非浏览器信号和异常速率；同站点、访客、页面限窗，同来源段异常峰值单列。共享网络和无 Referrer 不是作弊证据，不仅凭 IP 拒绝阅读；异常流量隔离后可按保留期限复核、校正、重算，禁止直接给用户处分。入口失败、超时、重试、同一阅读事件和反复表态不可叠加。
- **访客键不是匿名承诺。** 用站点内每日轮换 HMAC 摘要作日去重，不用 IP 与完整 UA 指纹。不把原始 IP、UA、Cookie、`session_key`、正文、评论内容或敏感 URL 写入评价/分析表、批次载荷或异常日志；访客统计不存账号 ID。登录账号外键只保留在需要一票约束、撤销和账号清理的评价业务表中，独立授权；聚合与榜单不带评价者身份。
- **评价防刷。** 首次投票、切换必须先过阅读门槛，按当前正式版校验；按账号、页面及脱敏网络信号作原子滑窗，其中滑窗是对最近一段时间内的请求总量限额。限流故障时拒绝评价写入，不影响正文或用 SQL 绕过。取消本人票不强制重读，但须登录、限流并防重试与跨标签页覆盖。异常复核、账号销毁或作者身份变化不得留下无效票数。
- **口径与隐私。** 页面、类别、站点均只按日分别去重，不建设跨日访客关联，不提供访客轨迹。来源与安全词条低频合并/隐藏，防止用不同筛选结果相减推断小样本。

### 6.3 留存、回收、恢复和彻底销毁

- **留存（D6）**：会话和日去重最多 48 小时，无访问者身份的运维日志最多 7 日，日表 13 个月，总表保留到 Purge。未结算批次不含访客身份，有容量和最迟补数期限。评价业务记录与短期会话不混存；撤销、账号销毁与页面 Purge 均检查清理和聚合一致性。保留的站点历史总量在生成时就不带页面标识，不提供可反推的历史筛选和导出。
- **软删除与恢复**：回收保留已结算的统计和审核记录，立即禁止新访问入账及公开榜单/推荐展示；复用回收权限，后台标“已回收”。恢复原身份可延续累计，恢复为草稿时不恢复采集，正式公开后才继续。下架、改私有、回收期间的流量不回补。
- **Purge（彻底销毁）**：只能由原有授权流程触发。同步清理可归因日表、总表、维度、评价及聚合、候选/审批、榜单条目和告警等 SQL 数据；同事务登记外部清理任务，提交后清 Redis、缓存及含该页的待处理载荷，失败可重试。已不可拆分的无页站点历史总量不承诺反扣 UV。不留可追溯的普通报表，不允许迟到事件或旧快照重建页面数据；备份恢复后先完成清理核对再开放读写。

## 7. 分期与验收

| 阶段 | 交付内容 |
| --- | --- |
| 第 1 期：可信看数 | 通用入口/详情、Redis → PostgreSQL 结算、PV/日 UV/访客日、基础阅读、导流和内部报表；验证权限、生命周期和缺测，不拿演示数据出榜。 |
| 第 2 期：评价与推荐 | 先验证并灰度四档评价；再引入低口碑告警、飙升/7/30 日榜、每日候选、逐篇审批及首页/栏目补位。先观察 2–4 周；不足 30 个完整日不放宽自动候选门槛。阅读数字可继续关闭。 |
| 第 3 期：指标与治理深化 | 三类专属指标、作者贡献、审核治理、导出与异常校正。游客评价、其他正文互动如需开放另行审查；不建设跨日 UV。 |

**实施验收，不是本轮测试结果：**

1. 新详情类型只需稳定身份、注册能力及可选模板标记即可接入公共指标，不改博客逻辑；首页、栏目、标签计导流而非深度。预览、未发布、已回收含祖先、受限及缓存旧页发来的信号均不生效，且已发布旧版本仍正常接受符合条件的公众访问。
2. 用固定测试数据手算 PV、UV、访客日、来源、完读和跳出；同一天跨三页全站只算一个 UV，跨午夜按规则归属。重复/乱序/丢包、后台标签页、首屏短文、代码复制成功与失败、文件分段、同一项目双外链均有独立用例。
3. 同时跑两个批处理 worker、模拟数据库提交前/后失败、Redis 重启、迟到事件、回收/恢复/Purge、版本更新；不重复入库，不泄漏新旧版本，不复活删除页。权限核对作者访问其他 `page_id`、合著但非 owner、换 owner、越栏编辑、导出和缓存隔离。
4. 逐项验收四档新增、切换、取消、重放、双标签竞态、作者自评、游客直调、账号清理和版本变化；用业务票表核对四档计数与总票。合成“高 PV 且差评充分”“1–2 个差评”“冷门高质量”“缺测”“异常流量”等反例，验收降权、精选阻断、人工提名与限期豁免。重复审批不重复置顶；下架、变私有和重发后旧版停止投放，首页“最新”和“精选”清晰可辨。
5. 检查看板中数据延迟、缺测、不可用、真正零值四种不同状态，以及隐私阈值和开关。按项目规则在隔离的 WSL2 `wagtailblog-test` 环境执行定向测试和真实 PostgreSQL/Redis 并发验证；真实服务、迁移等需单独授权。本轮未执行这些验收。
