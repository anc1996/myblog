# 站内音视频播放器与分栏预览

状态：待确认。本文是需求稿，不表示已经安装播放器、修改数据库或完成浏览器验收。

## 1. 目标与现状

作者写博客、指南或项目介绍时，可以像插入图片一样选择或上传 MP3、视频，并在右侧立即检查效果。读者看到统一的播放器。页面类型不需要分别写播放器。本期的「编辑」指调整素材与展示设置，不是剪辑、混音或转码。

- **现有项目**：`CustomAudioBlock` 和 `CustomVideoBlock` 已在 `content_blocks` 公共积木集中。`media_library` 已提供 Wagtail 选择器和上传入口；正文播放目前使用原生 `<audio>`、`<video>`，由 `/media-gateway/` 交付。视频已有素材级封面字段；在文章里改预览不应修改全站共享封面。
- **旧项目 `wagtailblog2`**：文章模板从本机静态文件加载 Plyr，模板资源标注 `3.7.8`。音视频脚本各自管理同类播放器互斥、倍速与错误状态；视频还有全屏、画中画、放大与折叠。借鉴这些体验，不照搬博客专用脚本、存储地址或下载按钮。
- **不改的部分**：第三方播放器仍由现有 `Embed` 管理；Spotify、网易云、Vimeo 等不换成站内播放器。Wagtail 草稿、发布、历史和回收规则不变。

## 2. 作者怎么操作

| 左侧：设置 / 源码 | 右侧：实时试听、试看 |
| --- | --- |
| 用现有 Wagtail 选择器选已有素材，或通过「上传并选用」加入素材。填写本次引用的标题；不修改素材库标题。视频展示选中素材已有的封面。 | 选择器返回后立即替换预览，不用先保存文章；标题修改即时反映且不重启当前播放。换素材停止旧播放器，新素材不自动播放。 |
| 首期提供「设置 / 源码」切换。源码显示可复制、只读的本块配置 JSON，方便理解存了什么；不显示 RustFS 对象键、凭据、签名链接。不允许粘贴任意 HTML、JS 或外链来指定文件。 | 共用前台播放器组件和展示规则。留出未选素材、加载、无权限、文件缺失和格式不支持的状态；窄屏改为上下排列。 |

后台使用 Wagtail 原有 `StructBlock`、选择器和分栏布局，按需补 Telepath 适配。Telepath 是 Wagtail 后台让新增、复制的积木在浏览器中正常工作的机制。作者始终通过 Wagtail 表单保存，右侧预览不写库、不创建页面版本、不自动公开素材；上传操作本身仍按现有流程创建受限媒体资产。

备选：若确实需要可编辑源码，再评估引入现成的代码编辑控件。只开放结构化配置或 WebVTT 字幕文本，通过同一套服务端校验转回表单字段，不把 HTML 或播放器脚本当成文章数据。先不为只读代码展示增加新依赖，可复用现有代码高亮。

## 3. 读者能做什么

- **音频（首期以 MP3 为主）**：显示标题、进度、播放/暂停、时长、静音/音量和倍速；控件按浏览器能力显示。附文字说明或逐字稿可使用已有正文积木。
- **视频（首期以 H.264/AAC 的 MP4 验收）**：显示标题、封面（若有）、进度、音量、倍速、全屏；画中画仅在设备支持时显示。保留视频自然比例，竖屏不裁切。旧站的放大弹窗和折叠先不作为交付条件。
- **共同规则**：不自动播放。同一页面播放另一段站内音视频时暂停前一个；控制台无重复初始化错误。跟随站点浅色和深色主题，窄屏不横向溢出；键盘可操作、焦点清楚，播放器快捷键不抢走作者输入。增强库未加载时保留原生控件；文件本身播不了时提示失败。
- **下载**：首期不增加明确的下载入口。能公开播放不等于能阻止另存；隐藏按钮不作为权限控制。
- **首期不做**：歌单、歌词滚动、波形、专用字幕编辑器、剪切、转码、HLS 自适应码率、上传续传。若文章含必要的语音信息，作者可以先给文字稿；若字幕是上线硬要求，需在实施前把受控 WebVTT 上传、交付和版本引用保护一并纳入。

## 4. 框架选型

| 方案 | 适用与取舍 |
| --- | --- |
| **推荐：Video.js 10 的 HTML 预构建包** | 同一库有视频与音频界面，播放站内 MP4/MP3 时用浏览器原生媒体元素，无需 React 或单独的流媒体服务。`@videojs/cdn` 是预构建制品，不能只复制 `video.js` 和 `audio.js` 两个入口，必须保留它们引用的相对路径和同版本共享分块。 |
| **备选：Artplayer 视频 + APlayer 音频** | 各有浏览器可用的发布制品，适合明确需要播放器差异化或音乐歌单/歌词的项目；同时引入两个依赖，意味着维护两套控件、降级、权限接入和验收。首期不需要。 |
| **参考：旧站 Plyr** | 上游现仅提供安全更新并推荐新项目采用 Video.js 10。复用旧站交互经验，不把 Plyr 加进新项目。 |

预构建包应从官方发布渠道下载，实施时核对确切版本、包目录、许可证与校验值，再写入 `vendor.lock.json`。优先验证官方 npm 包能否由现有 `sync_vendor_assets.py` 直接恢复；保持所需入口与全部依赖的相对目录，避免只取入口。验证生产 `collectstatic` 后仍能解析所有模块，不为播放器关闭全站静态资源哈希。第三方产物只落在忽略目录 `myblog/static/vendor/`，运行时不请求公网 CDN，也不开启统计扩展。具体版本和同步规则以小样验证为准。

参考资料：[Video.js 本地托管](https://videojs.org/docs/framework/html/guides/self-hosting)、[Plyr 官方仓库](https://github.com/sampotts/plyr)、[Artplayer 安装文档](https://artplayer.org/document/en/)、[APlayer 官方仓库](https://github.com/DIYgod/APlayer)、[Wagtail 8.1 自定义积木](https://docs.wagtail.org/en/stable/advanced_topics/customization/streamfield_blocks.html)。

## 5. 实施顺序和验收

1. **先验证播放器制品**：用隔离样例测试实际 MP3/MP4 播放、拖动进度、同页互斥和原生降级；分别核对开发静态路径与生产 `collectstatic` 后的路径。没有音视频积木的页面不加载厂商包。至少覆盖桌面 Chrome、Firefox 和真实移动 Safari；模拟设备不能代替 Safari 实测。
2. **接入公共前台积木**：保持既有 `audio`、`video` 块名和保存数据，Blog、Guide、Project 不分叉。用真实媒体检查首播、拖动进度及合法分段响应 `206`，起始位置超出文件长度时核对 `416`；生产代理模式也要单独验证。扩展名或浏览器声明的 MIME 不等于确认文件编码；未实测的旧格式不承诺可播，也不批量重写历史媒体。
3. **接入后台分栏**：选择、上传、取消、换素材、删除、复制、排序、保存后重开全部验证；不能串块、重复播放、留下旧音轨或使 Wagtail 丢失更改。用作者本人、其他作者及访客分别核对选择器、草稿预览和网关，不能因知道资源 ID 就获得权限；封面和媒体数据都不得暴露 RustFS 内部地址。保持现有视频、音频和封面的 `MediaReferenceRecord`，确认已被历史版本引用的文件仍受替换及删除保护。

权限边界：网关按素材可见性鉴权。受限文件不能靠预览变公开；已经公开并被其他页面使用的共享素材，不因本次编辑被错误收回。播放、拖动和错误回退都继续通过现有网关；旧站直链和隐藏下载按钮都不能替代权限检查。

**建议确认的范围**：采用 Video.js 10 预构建包；默认左侧表单、源码只读，右侧实时预览；先验收 MP3 和标准 MP4，字幕、歌词、转码与放大弹窗不列为首期功能。
