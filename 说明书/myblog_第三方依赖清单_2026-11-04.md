## PostgreSQL 切换后的依赖变化

- 项目已将 `mysqlclient` 声明替换为 `psycopg[binary]==3.3.7`，并安装成功；共享 Conda 中旧站 MySQL 包及系统库不卸载。
- 原附件已有 `jieba==0.42.1`，现加入项目直接依赖，不需要升级。中文正式文本和查询先用同版本词典分词，再接 PostgreSQL `simple` 配置、`tsvector` 与 GIN；PG 内置不自带中文分词，`pg_trgm` 只能辅助子串/拼写匹配。
- 当前 8 项直接声明为 Django、wagtail、psycopg[binary]、pymongo、redis、boto3、python-dotenv、jieba。原表与 JSON 不改写为 psycopg 原已存在或原环境已通过 PostgreSQL。
- PostgreSQL 18.6 启动、认证、UTF8 两空库、Windows TCP、11 项离线测试、四服务探针、两库严格检查与中文临时 GIN 探针通过；业务迁移、并发、完整搜索集成、性能与恢复演练未做。详见[PostgreSQL 切换记录](myblog_PostgreSQL切换记录_2026-11-04.md)；其他包的原候选版本、原统计和旧测试不自动变成当前验收结论。
- 最新 `pip check` 仍失败，仅报告旧站 `wagtailblog2==0.1.0` 要求 Wagtail 8.0.1、实际安装 8.1 这一条冲突；不卸载共享旧站包。

## 一、依赖概况与采用建议分类标准

本清单根据 myblog 第一阶段技术方案、服务选型及 Wagtail 8.1 官方依赖树，将现有环境中的 186 个包划分为 5 类：

| 采用建议分类 | 范围与说明 | 数量 |
|---|---|:---:|
| **核查时直接依赖** | 当时写入 `requirements.txt` 的核心包；当前切换后为 8 项，见文首 | 7 |
| **间接依赖随上游约束** | Wagtail、Django 或核心驱动的直接 / 间接依赖；部分附带平台或 extra 条件 | 43 |
| **开发工具** | 本地测试、代码规范、配置检查等工具，不进入生产运行环境 | 14 |

| **Conda运行库** | Conda 环境自带的底层 C 运行时、编译器支持、动态链接库与打包工具 | 41 |
| **合计全覆盖** | **附件 conda list 全部 186 个包恰好覆盖一次，无一遗漏** | **186** |

### 2. 关键架构结论速览
1. **直接依赖与上游间接依赖界限分明**：
   - 核查时 myblog 直接依赖为 7 个（`django`、`wagtail`、`mysqlclient`、`pymongo`、`redis`、`boto3`、`python-dotenv`）；切换后为文首所列 8 项，不改写原附件。
   - `django-ninja`、`django-tasks`、`modelsearch` 是 Wagtail 8.1 的标准上游依赖，需作为间接依赖随 Wagtail 8.1 约束协同维护，不能将其当成旧站残留盲目删除。
2. **废弃包与替代方案明确**：
   - **`uuid`**：使用 Python 3.13 内置标准库 `uuid`，PyPI 旧包不纳入新项目。
   - **`minio`**：项目依赖声明已移除，`wagtailblog-test` 环境中的 SDK 也已卸载；当前脚本使用 `boto3` 访问 RustFS。没有自动卸载其原有依赖，避免影响其他库。
   - **`wagtailblog2`**：新项目不引用这个旧站 editable 包；共享环境中它与 Wagtail 8.1 的版本冲突尚未解决。
3. **版本升级约束严肃性**：
   - 核对日的 PyPI 稳定版用于比较。候选版本必须满足 Wagtail 8.1 的依赖声明，并通过安装解析和功能验证后才能采用；本轮尚未执行这些安装和功能测试。
