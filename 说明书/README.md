## 请重点审核

- MySQL 中的发布状态与 MongoDB 内容版本如何对应，失败重试是否会泄露草稿或引用错误版本。
- 文件读取、HEAD、Range 和续传是否都重新检查权限；媒体历史引用是否能阻止误删。
- 数据库写入与对象上传不能一起提交时，残留对象、重试任务和回收流程是否完整。
- Wagtail 工作流在 MySQL 上的条件唯一约束限制，是否有明确的并发处理与验证方案。
- 每个实施步骤是否足够小，是否写清前置条件、验收方法和失败后的处理方式。

## 当前状态与限制

- 对象存储统一采用 RustFS，通过 `boto3` 访问；`minio` 和 `wagtail-modeladmin` 已从指定 Conda 环境卸载，Wagtail 自带后台保留。
- 服务准备和历史探针结果不代表业务功能验收；Django 当前仍使用默认的 SQLite 和本地文件存储配置。
- 共享 Conda 环境中的 `wagtailblog2==0.1.0` 要求 Wagtail 8.0.1，与已安装的 Wagtail 8.1 冲突；完整 `pip check` 仍不通过。
- 依赖升级建议尚未执行。JSON 和逐包表保留核查时的环境快照，后续卸载记录另列于文档开头。
- 尚未完成应用迁移、业务媒体接入、完整回退演练或部署。
- 明文服务凭据和 `.env` 文件只保留在本地，不包含在 Git 提交中。
